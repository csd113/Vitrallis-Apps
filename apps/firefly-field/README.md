# Firefly Field

Firefly Field is a quiet, fullscreen nighttime meadow for Vitrallis. Original
pixel-art layers, distant silhouettes, swaying foreground grass, occasional
shooting stars and independently blinking fireflies create an ambient scene
without network, audio or persistent storage.

## Rendering

The app uses the system SDL2 library through a deliberately small `ctypes`
binding; it has no pip dependencies. It follows the current
Vitrallis Shell renderer-selection policy: it enumerates SDL drivers, prefers
an advertised `opengles2` accelerated backend, tries every accelerated backend with VSync before retrying without it, verifies the resulting flags, and rejects known CPU
OpenGL rasterizers (including llvmpipe, softpipe and swrast). In `auto` mode it
then falls back to a fresh SDL software renderer if hardware attempts fail. `--renderer hardware` refuses to run
without verified acceleration; `--renderer software` skips GPU attempts.

It uploads a background, radial glow, firefly sprite and grass texture once,
then renders them with `SDL_RenderCopyEx`, alpha modulation and additive glow
every frame. The startup diagnostic uses Shell's
`event=renderer_initialized` shape and reports requested/actual mode, backend,
flags, dimensions and any automatic fallback reason. Acceleration flags alone
do not prove a physical GPU is rendering; validate the target driver separately.

The Shell has a shared Rust renderer crate, but no shared Python SDL API.
Firefly Field therefore owns its SDL lifecycle. It requires Python 3.8+ and a
system SDL2 2.0+ video driver. It is published as installable; target
PocketCHIP/Shell rendering and installation performance remain release follow-up
work rather than claims made by the renderer selection itself.

Run from any directory:

```sh
python3 /path/to/apps/firefly-field/main.py
python3 /path/to/apps/firefly-field/main.py --windowed
python3 /path/to/apps/firefly-field/main.py --renderer hardware
python3 /path/to/apps/firefly-field/main.py --renderer software --windowed
python3 /path/to/apps/firefly-field/main.py --check
```

## Controls

| Input | Effect |
| --- | --- |
| Pointer/finger | Nearby insects give the pointer room. |
| Click/tap | Briefly scatters nearby insects. |
| Space | Pause or resume. |
| Enter | Scatter insects at the center of the meadow. |
| R | Reseed the field. |
| H | Toggle the status overlay. |
| Up / Down | Add or remove 10 fireflies. |
| A / D | Add or remove one firefly, bounded to 30–260. |
| Left / Right | Reduce or increase glow. |
| P | Toggle system CPU and available DRM device utilization. |
| C | Cycle Night, Mist and Moss color moods. |
| W | Cycle Calm, Soft and Lively wind. |
| Escape | Exit through the normal window lifecycle. |

The complete keyboard reference is visible at startup. Press **H** to hide it
for an unobstructed meadow, or show it again at any time. Enter scatters the
center of the field without a pointer. Key repeat does not repeatedly toggle modes.

The performance overlay is off by default. CPU utilization is sampled from
`/proc/stat`. The DRM row shows a device-wide `gpu_busy_percent` counter only when exactly
one such counter is available; `---` means unavailable or ambiguous. SDL2 does
not identify which DRM card it uses, so this is not attributed to the app or
claimed as proof of GPU rendering. Renderer
selection and frame rate are not misreported as GPU load. Settings are
session-only and require no storage permission.

## Artwork and performance

Artwork is local to this package; see `assets/README.md` for provenance and
repacking instructions. The scene and reusable
sprites ship as PNG previews and bounded, zlib-compressed RGBA texture data.
They are decoded and uploaded once at startup;
per-frame CPU work is restricted to insect movement, blink state and a small
amount of control logic. The app does not use an animated CPU image, Pillow or
a full-frame texture upload. Unsynchronized fallback rendering is capped at 30 FPS; depth sorting occurs only when the population changes. Menu glyphs are cached in reusable textures. Supported accelerated SDL backends batch ordered sprites in a premultiplied atlas; other backends preserve individual sprite drawing. Paused views wait for native events and redraw counters at most once per second. The package icon is generated by
`assets/make_icon.py` using only the standard library.

Desktop tests do not certify SDL driver selection, fullscreen behavior, touch,
GPU performance or App Center installation on physical hardware.

Physical scanout synchronization is still being validated; accepted VSync flags alone do not prove a tear-free display. See the [rendering contract](../../docs/rendering.md).
